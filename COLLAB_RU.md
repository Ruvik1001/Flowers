# Руководство по коллаборации

Монорепозиторий системы управления цветочным магазином Flowers.

## Структура репозитория

- `backend/` — API и серверный домен (команда backend)
- `frontend/` — клиентское приложение (коллабораторы frontend)
- Корневые документы: `README.md`, `README_RU.md`, `COLLAB.md`, `COLLAB_RU.md`

## Обязательные долгоживущие Git-ветки

Коллабораторы **обязаны** использовать следующую модель веток:

| Ветка | Назначение |
|---|---|
| `master` | Стабильная интеграционная ветка |
| `backend` | Интеграционная линия backend |
| `frontend` | Интеграционная линия frontend |

### Рабочий процесс

1. Фичи backend ветвятся от `backend` (пример: `backend/feat-supplies`).
2. Фичи frontend ветвятся от `frontend` (пример: `frontend/feat-sales-ui`).
3. Feature-ветки вливаются обратно в `backend` или `frontend` соответственно.
4. Проверенные изменения переносятся в `master` по согласованию (PR/review).

Не пушить feature-работу напрямую в `master`, если это явно не согласовано.

## Правила документации backend (для потребителей API)

- После каждого коммита, затрагивающего контракт для frontend, добавить/обновить API-документацию.
- Маска файла документации: `xx_id_desc.md` (`xx` — порядковый номер, `id` — идентификатор коммита, `desc` — краткое описание).
- Документация пишется **до** создания коммита.
- Postman-коллекция должна быть синхронизирована.
- Обязательные разделы в каждом файле API-документации:
  - Заголовок
  - Краткое описание файла
  - Описание ручки
  - Имя ручки
  - Принимаемые заголовки (+ обязательность)
  - Принимаемые поля/параметры (+ обязательность)
  - Принимаемые тела (+ обязательность)
  - Примеры запросов и ответов
  - Ожидаемые коды ошибок и сообщения об ошибках

## Общие инженерные правила

- Реальные файлы окружения в git не коммитятся; только `.env.example`.
- Все runtime-настройки задаются через переменные окружения.
- Запросы должны логироваться и трассироваться (предлагается использовать [https://github.com/Ruvik1001/MonitoringPLTG](https://github.com/Ruvik1001/MonitoringPLTG) на сервере).
- Целевое покрытие тестами: ≥ 90%.
- Перед началом новой фичи перечитать архитектурную документацию.
- Поддерживать актуальность `README.md` (EN) и `README_RU.md` (RU).

## Контакты / зоны ответственности

- Backend: команда backend (линия `backend/` в репозитории)
- Frontend: команда frontend (линия `frontend/`)
